# 跨天节点与化学辅助：开发交接

日期：2026-11-15。基于 0.9.2；本轮未升版、未推送。

## 需求与实现

### 跨天内存节点

- 默认开启 `CustomerCheckpoint.KeepPreviousDay`，设置面板可关闭。
- 同一场景、同一 PlayerStore 的正常睡觉跨天保留昨天剩余节点；不是重新抓取昨天，也不补回已淘汰节点。
- 每个日期独立最多 20 个内存节点，**包括手动节点与自动闭店节点**。进入第三天释放更早节点。
- 同一天的自动闭店节点仍只保留最新一个；闭店期间的手动节点不再覆盖自动闭店节点，也不会相互覆盖。
- 面板最多 48 行，节点带日期；原有文件开业前节点、失败提示保留。
- 选择旧节点只浏览历史，不立即删除未来节点；新顾客、新手动/营业节点、回溯后重新睡觉会提交新分支。
- 关闭保留选项会释放其他日期节点。离店、换场景、读档、关 Mod 的原清理边界不变。
- 跨天恢复只允许相邻日期；已被保留的未来一天可以往返查看，不能通过反复睡觉累积无限天数。
- 跨天时增加夜间结算、黑屏、晨报/日历、睡前界面、游戏结束、原版漏斗队列/传输门控。请先关闭晨报，再从面板回溯。
- 不调用 SaveGame，不撤销游戏自己正常睡觉时写出的磁盘存档，不回退 Steam 成就或第三方 Mod 自己的静态/外部状态。
- 原对象图、视觉预检、全量最终差异校验和失败后重载保护均保留。原视图被游戏/第三方销毁时仍会在写入前拒绝，不降级成不完整恢复。
- 昨天节点额外占用内存，保留视图也可能更多；原单节点对象/字节预算不变。

**首节点耗时**：原布局/读取器缓存本就跨天保留，普通 Clear 不清它们；新功能没有重复复制昨天节点，也没有追加 oracle。不能宣称解决首次布局初始化。完整图抓取开销仍存在，需实机看 `CAPTURE captureMs`，不能仅凭新功能推断提速。

### 化学标注与空容器

- `Chemistry.ExtendedContainers` 默认开启：化学分析与改名最小 150mL，无最大容量。关闭时回到原容量规则。
- `plant_matter` 不再参与主成分命名竞争，但仍计入总液量；没有有效主成分时保留原名，不误称为水。
- `Chemistry.EmptyContainerNames` 默认开启：150mL 微型空瓶、水罐、水桶、带实际升数的空储水罐。
- 核对当前游戏中文表：`item_med_bottle_small_pink_name=脂合剂瓶`，原版容量已经是 150mL，不修改实际容量；`item_water_pitcher_name=水罐`、`item_water_jug_name=桶装水`、`item_water_tank_name=储水罐`。
- 水罐和储水罐虽有 GRADUATED_CONTAINER_TAG，不当成实验量器排除；滴管、真正量器仍不改名。
- 只替换原有 tooltip/拖拽提示作用域，不修改物品真实名字、任务或交易列表。

### 自动搅拌

- `Chemistry.AutoBlend` 默认开启，受化学辅助总开关控制。
- 只在玩家单件/群组拖拽提交期间排队；加载、回溯、原版夜间结算不触发。
- 空容器可接受可搅拌物；非空容器比较主要产物集合。排除水、酒精、植物质及低于总量 1% 的成分；恰好 1% 保留。
- 三种糊糊分别归一为萃取液/咖啡因：`dream_cap_mush -> dream_cap_extract`、`nightmare_cap_mush -> nightmare_extract`、`coffee_mush -> caffeine`。
- 主成分按满足条件的**集合相等**判断，不仅比较最大一项。混合产物不会与单一产物误匹配。
- 单件不匹配仍能放入，供手动配方使用；群组不同产物留在来源。
- 仅对自动搅拌目标临时使用原版逐件群组放入路径，不影响其他库存的保持队形群拖。每次完整原版转移结束后搅拌，释放输入网格，再放下一件。
- 额外批次计划锁定主产物并预留容量，重复准入检查不重复计数；每批完成后清掉体积预留，但保留整次手势的产物锁。
- 单件在 EndDrag 完成后才销毁原料，避免原版拖拽后续访问已销毁物品。
- 产量按原版每成分四舍五入及模块损耗计算；整件产量放不下就停下/留在原处，不调用会丢弃多余液体的搅拌路径。不会拆一件原料做部分搅拌。
- 调用原版 ChemicalHelper.BlendInto；不另写一套销毁/原料扣除逻辑。

### 自动萃取

- `Chemistry.AutoExtraction` 默认开启，受化学辅助总开关控制。
- 原版 TransferLiquid/AddLiquid 成功增加酒精时触发；任意正量酒精即可，不消耗酒精。
- 全部三种糊糊分别转为等量萃取物，再额外产生等量植物质。允许液体总量超过容器容量，不调用 RemoveExcessLiquid。
- 写入前完成整个转换计划；注册表缺目标成分或结果超过原版 int 总量范围时不转换。
- 写入/校验异常时恢复原标签并重新校验，避免只转换部分标签。
- 只处理玩家拥有、位于库存中的非酿酒液体容器；加载/回溯/自动搅拌内部加液/原版夜间结算不触发。手动倒入与正常加液的实际表现需实机确认。

### 隔夜预览

- `Chemistry.FacilityPreview` 默认开启，受化学辅助总开关控制；原生 OnCreateTooltipLate 追加。
- **只读**：直接 TryGetValue 读取 modifiedState。游戏的 GetTagReadonly 实际会补缺失标签，本实现不靠它补字段。
- 不创建物品、不调用原过夜/工作/收获回调、不推进 RNG、不模拟保存，不临时改夜间标志。
- 净水器：污染度曲线、性能预算、净化上限、粒径/污染物优先级、组内比例与末项余数；显示去除明细和预计水占比。
- 蒸发器：挥发成分比例分配、性能、质量回收率、仅回收酒精模块、原版逐成分容量上限。缺回收容器红色警告，但仍显示预计蒸发量。
- 水培：电力/水量、当前工作速度、营养消耗、污染健康损失、比例耗水、净化性状、成熟门槛；成熟显示本体产物与数量/随机区间，否则显示次日进度。水不足红色警告。芦苇显示净化明细与滤芯/种子。
- 养鱼系统：仅有活阴沟罗非鱼时显示，按当前鱼重和原版水相对污染下限估算三类污染物去除量。明确不计生长、死亡、滤芯；**不是整个鱼池净水量的精确承诺**。
- 电源区分普通电池、超科技电池、变流器；变流器按已选择夜间服务而非白天付款判断。
- 预览标题明确“按当前内容”。化学夜间反应、漏斗补料、鱼死亡/生长、第三方自定义回调、随机遗传/附加收获都会影响最终结果。本轮没有执行这些有副作用的回调来假装精确预测。
- 成分名沿用原版语言键/英语回退；新说明仅中文/英文。未知语言不修改游戏 locale，也不要求新增翻译表。

## 离线验收与限制

已通过的阶段验证：

- Release 构建 0 警告/0 错误。
- 403 项参考测试，包含新增化学规则、预览算术、分批预留与每日限额/分支/清理。
- 500 组预览耗水与当前游戏 WaterHelper.SplitProportionally 的精确对照。
- 原版 TagSystem 字典版本检查：只读查询不创建缺失标签；149/150mL、50L、刻度水罐/储水罐/滴管排除实测。
- Harmony 目标签名、漏斗静态门控字段契约检查；发布扫描仍只允许 files，不能添加动态代码/外部反射。
- 既有完整静态布局生成、Mono 原生对象图往返、预算、MVID 拒绝测试继续运行。

这些检查**不等于 Unity 活体测试**，尤其尚未覆盖：

1. 第一天建立节点 -> 睡觉 -> 关闭晨报 -> 回到昨天营业/闭店/手动节点 -> 再回今天节点。
2. 回到昨天后继续操作并睡觉，确认原今天分支不再出现；进入第三天确认淘汰；关开保留设置。
3. 群拖混合咖啡/菇类到空瓶与已有产物的搅拌机；超过输入格子容量；超过瓶容量；不匹配原料原位保留；其他库存保持队形不回归。
4. 单件不匹配原料放入后手动搅拌；关开自动搅拌设置。
5. 三种糊糊混装后倒入极少量酒精，核对三类萃取物、植物质、酒精和超容量总量；回溯前后各一次。
6. 150mL/3L/6L/变容储水罐的空名、主成分、植物质；切换中文/英文/其他原版语言。
7. 四类设施查看 tooltip 不改变内容/随机数；对比睡前预览和实际次晨。分别试断电、缺水、缺回收容器、模块、芦苇与有/无阴沟罗非鱼。
8. 顾客贴图、交易、售出物品/旋转/群拖旧回溯矩阵。

开发期间不主动启动/结束游戏，不操作存档。只有确认游戏已关闭才部署；备份与双 DLL 哈希见部署记录。新功能默认开启，实测前建议使用可恢复的游戏存档副本。
