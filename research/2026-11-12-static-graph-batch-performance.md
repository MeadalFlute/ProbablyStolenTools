# 静态图性能优化批次

日期：2026-11-12。版本保持 0.9.0，未推送。

本批将剩余已识别、可保持原始字段语义的优化合并交付，全部离线验证后只部署一次，不再逐项要求实机测试。

## 完成项

| 项目 | 实现及边界 |
|---|---|
| 结构体数组重复拆箱 | 捕获、普查和差异扫描共用显式只读 pass；同一数组元素的相邻字段只拆箱一次。仅缓存一个元素，按数组身份/元素索引匹配；逐对象捕获重置，结束 pass、写入、可能执行自定义值比较的边界均清除。普通独立读取不使用该缓存；恢复写入不启用只读 pass。 |
| 逐槽重复查表 | 标量比较/取值复用已解析的 owner 和 Storage；单个访问器只暂存当前 owner 的存储描述，不暂存字段值。Describe 及 Dispose 清除该描述缓存。 |
| 有界共享字段描述 | 仅静态后端跨访问器共享只读类型/数组布局。类型键包含 Unity 边界、快速读取模式和元素标记，数组键包含类型、长度、快速读取模式；局部根字段筛选始终单独建立。两类共享缓存各最多 4096 条、65536 槽，满后仍正常建立节点局部描述，不漏存、不放宽预算。 |
| 首次字段表初始化 | 同一个 Module 的 MVID 只验证一次，仍在公开字段表之前验证完整注册表；没有跳过任何模块或版本拒绝检查。 |

共享内容仅包含槽名、固定索引、FieldInfo 路径及不绑定业务对象的读取器，不包含节点对象、委托 target、字段值或值令牌。Dispose 不清空其他节点正在使用的只读描述。独立普查访问器继承读取/共享设置，但对象保留和令牌表仍然独立。

不调用游戏业务 getter 替代原始字段访问，即使构建时能看到简单 getter，运行时 Harmony 补丁仍可能改变其行为。不恢复运行时代码生成，不修改加载器/扫描器，不减少集合物理字段、预算、普查、预检、owner 修复或最终全量校验。

## 离线验证

入口：`scripts/Test-StaticLayouts.ps1 -GameDir <GAME_DIR>`。

除原有参考测试、原生实体/图夹具、静态字段表精确对照、能力扫描、可重复构建及错误 MVID 拒绝外，新增游戏 Mono 夹具覆盖：

- 两个数组相同索引的隔离，标量/引用写入后的缓存失效；
- pass reset/end、捕获失败后的清理，以及 pass 外直接修改的可见性；
- 独立访问器设置继承、快速/普通读取描述隔离；
- 部分根字段不扩大覆盖面，同一 owner 重新 Describe 后不使用旧描述；
- 一份访问器释放后其他访问器继续读；释放不保留最后的 owner；
- 全局描述条目/槽数限制及无业务 target。

所有新增测试/基准均在离线夹具，不编译进发布 Mod；生产不增加基准、自动测试或逐槽日志。

## 大对象图对照方法

`MonoHost` 新增可选 `--benchmark`，只在独立进程加载游戏 Mono 和无构造函数的数据对象，不启动游戏/Unity，不运行买卖回调，不读写存档。

示例：

```powershell
dotnet run --no-build -c Release --project tests/CapabilityMigrationProbe/MonoHost -- `
  "<GAME_DIR>" tests/CapabilityMigrationProbe/MonoFixture/bin/Release/netstandard2.1/MonoFixture.dll `
  src/ProbablyStolenTools/bin/Release/Mono/ProbablyStolenTools.dll --benchmark
```

固定图：2000 组物品/形状/原始 byte[]、List 和 Dictionary，每组 16 个 TagState；共 80002 对象、728000 槽、5824000 逻辑字节。并非玩家存档，也不含真实 UI。每轮分别计时捕获、普查、预检、业务写入、最终校验及 reconcile 扫描/应用；修改精确 Tag 值和普通 Dictionary Entry 引用，恢复后检查内容、规模/预算一致、diff=0。

每个进程 8 轮，轮间在计时外回收已释放节点。第 0/1 轮作为冷启动/暖机，不参与稳态汇总。候选交替关闭/启用数组复用和共享描述；旧 DLL 无这两个开关，标签只用于对齐运行顺序。新旧 DLL 各三个独立进程，按相同奇数轮 3/5/7 比较生产默认模式，避免把首次加载收益混入稳态收益。离线耗时不等于完整实机回溯耗时，尤其不包含 Unity refresh、geometry 和顾客视觉刷新。

原始输出：`out/batch-benchmark-before-{1,2,3}.log`、`out/batch-benchmark-after-{1,2,3}.log`。初始 16 万对象探索输出为 `out/batch-benchmark-candidate-1.log`，其 GC 条件和规模不同，不参与正式对照。

## 统一实机验收

仅此一次部署后集中验证：

1. 首节点、后续自动节点和手动节点；观察创建卡顿及面板可用性。
2. 多节点反复前后回溯；售出/移动/旋转物品、嵌套容器、柜台及顾客贴图。
3. 恢复后框选/群拖、交易和送客；确认无空气占用或重复成交。
4. 保留同一会话的 CAPTURE captureMs 和 RESTORE ms(...) 行；确认 diff=0、releaseOk=True，没有新增 schema fallback/超限/能力错误。

本批完成的是所有已识别的保守优化项，不声称消除了固定 FieldInfo 读取成本，也不承诺恢复到旧动态编译后端的速度。进一步替代私有字段反射需要新的架构/兼容性验证，不在本次无实机协助的批次中冒进。
