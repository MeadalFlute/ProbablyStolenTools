## 2. 实现

原先每个数组都生成独立 StateSlot[]、Storage[] 和逐元素字段名；相同类型/长度的数组实际使用相同字段路径、偏移、元素索引和读取器。

ManagedStateAccess 新增**每访问器内**的 `(数组 Type, Length) -> TypeSchema` 有界缓存：

- 在数组合法性、元素类型及剩余预算检查之后才尝试命中。
- 命中时复用不可变的描述数组；字段读取和写入仍根据当前 owner ID 找到各自的原数组。
- 不缓存数组实例或标量值，不跨快照共享，也不更改元素 offset=`i * stride + j`、Storage.Index=`i`。
- 缓存最多 4096 个形状、累计 65536 个描述槽；达到任一预算后，未缓存形状走原完整展开路径，已有形状继续复用。
- Dispose 清理缓存与统计，不让释放的节点影响其他节点。
- 图仍为每个数组分别记账和保存全部槽位/引用，包括集合 Count 外的容量。逻辑 bytes 不变，不降低 MaxSlots/MaxBytes 的使用量。

生产默认开启描述复用；内部构造参数可关闭，仅供离线对照，未增加用户设置。

每份 CAPTURE 的原摘要增加：

```text
arraySchemas(cached=...,hits=...,slotsReused=...)
```

cached 是当前缓存形状数；hits 是重复描述命中次数；slotsReused 是命中形状的描述槽累计数。**它们不是业务槽位减少量，也不是实际节省字节数。** 没有添加逐对象日志。

不改 StateGraph、捕获门控、业务遍历边界、恢复/清理顺序、完整校验或随机源，不分帧。

## 3. 回归与基准

新增五项回归，全部 **90 项**测试通过：

1. 反射/编译读取模式都可共享相同形状描述，但不同数组仍读出不同的实际值；类型、长度或快照不同时不串描述。
2. 两份同形嵌套结构体数组的每元素值及不同引用正确恢复；多个节点往返、释放其中一个节点不影响另一个。
3. 缓存命中前仍执行预算检查，不绕过第二步的剩余额度拒绝。
4. 描述槽上限、形状数上限分别有效；大型未缓存数组保持完整描述。
5. 稀疏字典集合的容量、对象集合、全部槽位、逻辑字节、来源路径与关闭复用的对照一致；扩容/清空/新增后恢复原数据。

Mono Release 构建 0 警告、0 错误；55 个挂点、73 个字段及实际 PlayerStore / StoreStation / GameItemElement 图往返通过。官方 scanner 能力仍为 files / reflection-external / dynamic-code，HardFlags / Error 为空。
