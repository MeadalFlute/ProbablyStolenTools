# QuickSL 0.9.10 F9 Hotfix

## Scope

- Based on published 0.9.9 (`57265389669478f91474a8a074fcce6c7772ce7e`).
- Isolated worktree: `D:\Program\GameProject\ProbablyStolenMod-099fix`.
- Branch: `hotfix/0.9.10-f9`. Feature-split worktree and Shift Toolbox are untouched.
- No new features, optional dependencies or capabilities. Mod identity and settings remain unchanged.

## Reproduction And Cause

The local 0.46D Player.log reports Proper Signboards 1.0.48 `running=False`, followed by
`SignboardCompatibility.Api..cctor` throwing NullReferenceException from `AccessTools.Field(string)`.
The call originates from `OptionalCaptureReady -> TryCaptureDayStart -> RewindOverlay.Update`.
The overlay catches it, permanently sets `_inputBroken`, then skips F9 and other hotkey handling.
Automatic checkpoints fail on the same readiness path.

Mono can initialize a beforefieldinit holder when compiling a method that references its fields,
even though an earlier enabled-mod guard would return. A missing optional type must not be
resolved by a field initializer. The existing absent-mod fixture only called Root, not CaptureReady.

The original Workshop DLL fails the new direct-readiness reproduction under the actual game Mono.
The fixed DLL passes the same entry. The player's short pasted log alone cannot prove that their
report has this exact cause, but local reproduction and the full stack establish a real defect.

## Changes

1. Move optional API resolution into one guarded, cached method. Static initializers contain no
   optional lookups; inactive mods do not trigger the resolver. Keep literal names so the official
   scanner does not classify a generic computed-Type helper as reflection-external.
2. Missing/changed API remains unsupported and skips only the optional adapter, matching existing
   policy. Existing checkpoints still reject lost owner/inventory/build identities.
3. Unexpected capture readiness exceptions defer the checkpoint with a once-per-session diagnostic.
   They do not admit incomplete checkpoints or escape to the overlay's permanent input-failure gate.
   No general change to unrelated overlay exception policy.
4. Include the existing native detached-view fix: record whether a parent existed at capture;
   still reject destroyed nodes, destroyed captured parents and missing render components.
5. Advance Plugin/MelonInfo and all three manifests to 0.9.10. Retain stable 0.46D / beta 1.0.0.16.
