# Generic snapshot beta

Branch: `beta/generic-snapshot`, base `6902aa9` (committed 0.6.0).
Version: `0.7.0-beta.1`. Runtime: full-release Mono only.

## Implementation

- Traverse third-party instance fields reached through the existing game roots.
  Support collections, cyclic/shared graphs, native base fields and delegate targets.
- Preserve original objects. Never instantiate mod data, evaluate properties, invoke
  gameplay callbacks, scan static storage or force a save/load.
- Per-capture metadata caches avoid repeatedly classifying the same runtime types.
- Skip infrastructure: Unity native objects, tasks/threads, coroutine iterators,
  disposable resources, weak registries, reflection objects and native handles.
  Inspect actual reference values so an `object` field cannot hide a task.
- Unsupported third-party field shapes degrade with bounded diagnostics. Native
  pointer fields and global capture limits still fail closed.
- Custom nullable structs remain unsupported; do not serialize them as scalar
  tokens or invoke third-party equality/hash implementations.
- Coverage records up to 32 details per capture. Restore diffs cover recorded
  fields only; external static state is explicitly untracked.

No third-party mod identifiers or adapters exist in production code.
Third-party names appear only in optional real-DLL regression tests.

## Validation

- Mono Release build: zero warnings/errors.
- `CheckpointTests`: 60 cases, including 13 new external-assembly cases.
- `ReleaseCompatibility`: 51 Harmony targets, 68 fields, actual official scanner,
  matching plugin/manifest versions, native XML settings round trip, real
  PlayerStore/StoreStation/GameItemElement graph round trip.
- `ModCompatibility`: 5 actual mod data scenarios through the built beta DLL.
  CorpPresence state/dictionary and JsonIgnore queued-day fields, actual one-shot
  closure, Pen machine closure/native item, Cyber supply data/arrays/back-and-forward,
  native modData strings and insertion/removal.
- Data tests allocate uninitialized DTOs only. No mod entrypoints, save APIs,
  gameplay delegates or running game process are used.

These checks do not establish Unity gameplay acceptance or full third-party compatibility.
Independent static roots, asynchronous effects and custom renderer/inventory lifecycles
are deliberately outside this patch.

The optional old Demo build was attempted and failed with 9 errors in unchanged
DoubleClickInspectionPatch.cs and Rewind.cs (IL2CPP list/delegate mismatches).
This beta does not ship a Demo DLL or change those unrelated modules.

## Publication and acceptance

Package via `scripts/Package-Beta.ps1`; includes Mono DLL/manifest, installation
and rollback guidance, release notes, external archive/file hashes and source commit.
Publish only as a prerelease from this branch. Do not update the stable Workshop
item, deploy over the local stable mod, merge to main or change trust/enable records.

Human acceptance: ordinary game without other mods first, then each target mod and
the combined set; customer capture, modified item/transaction rollback, one-shot
interaction reuse, retained future nodes, closed-shop history and scene/day expiry.
Wait for active animations/sorting to finish. Collect all three log files.

The original workspace retains its uncommitted shutter fixes. They are not part of
this beta; do not accidentally absorb or overwrite them during a later merge.
Post-write restore errors retain the existing fault-and-reload behavior. This patch
does not implement complete transactional rollback of both business graph and views.
