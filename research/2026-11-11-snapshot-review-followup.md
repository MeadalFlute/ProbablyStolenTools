# 快照评审跟进与真实游玩阶段分布

## 评审核对

1. 数组预算此前使用 slot.Size，但当前 Mono 的 Add 将所有标量描述都设为 8，decimal 也不例外，故当前代码没有因 byte/bool/decimal 的物理宽度出现误拒或晚拒。仍采纳显式令牌语义：统一 ValueTokenBytes=sizeof(long)，用于描述、预算和普查；引用按 IntPtr.Size 计算，通用后端仍按实际 ReadValue 字节计数。
2. array.Length 上限并不单独保证 length × stride 不溢出，现有普通元素跨度未见触发。需求改为 long 乘法，先预算检查，再转 int 分配；SnapshotDescriptionLimitException.RequiredSlots 改为 long，补充带需求计数的 Message。StateGraph 仍转换成含路径、已处理计数和配置预算的 SnapshotLimitException。
3. RESTORE 的 Dispose 异常以前会在重置 timeScale/Restoring 后向外传播，阻止成功摘要。本轮捕获这类临时普查释放异常：已完成恢复照常输出 RESTORE OK，但 releaseOk=False；另外输出 CENSUS RELEASE FAILED 并进入错误日志。原有写入失败处理不变，不把清理异常误当成需要重放恢复的业务失败。
4. AGENT 明确 MaxObjects 包括已发现身份/队列前沿。相对旧代码更早拒绝，失败时展开数可能未达上限；同一稳定图的最终唯一身份数若在限额内，成功边界并未缩小。
