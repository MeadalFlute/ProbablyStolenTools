# QuickSL 0.7.0-beta.1

这是正式版 Mono 的通用快照兼容性测试版。尚未通过 Unity 内组合模组验收。
稳定版不受此预发布影响，测试通过后才考虑合并。

## 本次变化

快照会继续遍历可达的第三方业务字段、集合和回调闭包，
恢复它们原来的数据和对象引用，无需按 Mod 名称编写适配。
第三方派生物品保留原生基类字段的捕获。

线程、后台任务、协程执行器、文件/原生句柄、资源持有对象与 Unity 原生对象不参与回放。
不支持的第三方字段会被跳过并记入日志，避免单个字段中断全部捕获。

## 安装与回滚

1. 退出游戏，备份当前 QuickSL 的整个 Mod 目录以及正在使用的游戏存档。
2. 用压缩包内 `ProbablyStolenTools` 目录中的 DLL 与 manifest 替换原来的两个文件。
   保留原有配置。使用工坊稳定版时，先停用/取消订阅该版本，避免本地与工坊重复加载。
3. 确认游戏 Mod 列表显示 `QuickSL (Generic Snapshot Beta)`、版本 `0.7.0-beta.1`。
   只运行一份 QuickSL。测试版使用与稳定版相同的 Mod ID 和配置格式。
4. 回滚时退出游戏，将备份的两个文件恢复，或移除本地测试版后重新订阅稳定版。

本包不会安装额外加载器，不自动修改 Mod 启用/信任记录，不主动保存游戏。
F6 仍是同店、同日、同场景的内存回溯；离店、跨日、换场景后旧节点仍然失效。
F7/F5 是原有整日文件回退，不是这次兼容测试的重点。

## 建议测试

先单独启用测试版检查原版行为，再逐个加入目标 Mod，最后组合测试。

1. 顾客开场对话结束后确认节点生成，进行交易、议价或修改 Mod 物品状态。
2. 按 F6，核对现金、库存、物品属性、可再次议价，以及第三方物品/交互状态。
3. 连续接待至少三位顾客，在旧节点与后续节点之间往返；再招待下一位，
   确认未来分支此时才截断。
4. 闭店后在当日节点间恢复；离店/次日确认旧内存节点失效。
5. 涉及整理、供货动画等功能时，等它们结束再测试回溯。

## 覆盖范围

本版只覆盖从原有游戏快照根可达的实例字段。
Mod 独立静态状态、额外仓库、异步任务及自定义视图刷新不保证兼容。
不调用第三方 Save/Load/Reset，不执行其 getter、构造器或业务回调，
不扫描静态字段，不保存整个 Unity 进程。

因此，不能把“生成节点成功”或日志里的 `diff=0` 当成整个 Mod 已正确回溯。
`diff` 只比较实际记录的字段。

## 反馈

请提供第三方 Mod 名称/版本、具体操作顺序、预期与实际差异，以及以下日志：

- `%LOCALAPPDATA%Low\Questing Goose Studio\Probably Stolen\PSTools.log`
- 同目录 `PSTools_history.log`
- 同目录 `Player.log`

日志增加 `[Snapshot] COVERAGE` 与 `[Snapshot] SKIPPED`。
`externalStatics=untracked` 表示没有追踪第三方静态状态；
`skipped` 是跳过的字段/对象数量，每次捕获最多记录 32 条详细原因。

本包从已提交的 0.6.0 开发，未包含稳定主目录中尚未提交的卷帘门看门狗修复。
